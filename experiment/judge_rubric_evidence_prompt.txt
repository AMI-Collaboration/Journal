## Evidence rules (identical for every plan)
A score of 5 needs the required evidence to be CONFIRMED, not merely the absence of a visible defect.
For every required goal, every precondition and every collaboration, record one status:
  satisfied   : the plan lines (action ids) that establish it are named
  violated    : the plan lines that break it, or the needed line that is missing, are named
  unverifiable: the given information is not enough (say exactly what is missing)
- Unverifiable is neither success nor failure. Do not turn it into a deduction and do not count it as achieved.
  If a CORE condition is unverifiable, do not give 5 for that criterion.
- Judge by the STATE an action produces, not by its name, intent or tag. A step that only names an intent,
  or an action that does not fit its object (for example "pour" with a faucet as the object), does not produce
  the state.
- A missing item cannot be quoted: for a missing goal or prerequisite, state which goal or precondition is
  needed and name the nearest related action id, or write "no related action".
- Count independent root causes, not lines. One cause that pushes several lines past the deadline is ONE
  deadline violation. One cause may affect several criteria only if it has a different consequence under each.
- If a required goal is explicitly left undone because no robot present has the capability for it, and the plan
  says so, that goal is unattempted (honest incompleteness), not fabricated success. A fabricated workaround
  scores lower on that goal than an honest "cannot be done".

## Scoring Instructions
Score each criterion on a 0-5 scale. Each criterion below gives an explicit description for every point from 0 to 5 --
find the single description that best matches the plan and use that score; do not interpolate between two
descriptions or average across them.

---

### TF: Task Fulfillment -- 0~5

Evaluate whether the plan fulfills the required goals of the task using real objects from the room list.
A goal counts as achieved only if a valid action's result, or a confirmed initial state, satisfies the required
state by the deadline.

- 5: All required goals are achieved with concrete actions on real (non-hallucinated) objects, within the deadline.
- 4: Nearly all required goals are achieved; only one minor gap or a small, non-blocking hallucination remains.
- 3: Most required goals are achieved, but with a clear gap, inefficiency, or a minor deadline slip.
- 2: Some required goals are achieved, but notable gaps, hallucinations, or a deadline violation exist.
- 1: At most one required goal is achieved; most core actions are missing or the deadline is clearly exceeded.
- 0: No required goal is achieved, or the plan is absent or entirely irrelevant to the task.

Rules:
- Goals achieved via hallucinated objects count as NOT achieved.
- If one required core goal is blocked (no valid action reaches its state), the TF score is at most 2.
- If the plan's total time clearly exceeds the task deadline, apply deduction.
- If two robots handle the same object redundantly, apply small deduction.
- Partial credit: correct intent and structure deserve credit even with minor hallucinations, but a plan with
  no valid action for a goal does not get that goal.
- Cross-room collaboration moving objects toward the right destination deserves partial TF credit.

---

### GF: Grounded Feasibility -- 0~5

For each action check: the object exists, the robot can manipulate it, the action is within the robot's CAN list,
the robot can reach it, and the robot observes it or receives it. Separate confirmed violations from
unverifiable cases.

Capability checks (from Agent Configuration):
- A Mobile_Light robot performing heavy furniture pushing = violation.
- A Gripper robot leaving its room without HELP/PASS context = violation.
- Any robot performing actions beyond its stated CAN list = violation.

Grounding checks:
- Hallucinated objects (not in actual room list) = violation.
- Vague expressions: "any ...", "something", "ensure", "check", "accessible location" = violation.
- Robot using information it cannot observe (objects in other rooms it never received) = violation.
- A robot holding multiple objects simultaneously = violation.
- An object that is not in the room list because the input lacks the information is "unverifiable", not a violation.

Scoring:
- 5: No capability or grounding violations; every action is physically executable using only
  legitimate local or received information, and this is confirmed.
- 4: At most one minor violation (e.g. one vague expression) that does not affect physical feasibility.
- 3: A few isolated violations exist, but the plan is still mostly executable as stated.
- 2: Several violations (hallucinated objects, a capability mismatch, or holding multiple objects
  at once) undermine multiple steps, though some of the plan remains executable.
- 1: Violations dominate the plan; most actions are not reliably executable given the stated capabilities.
- 0: The plan is entirely incompatible with the robots' stated capabilities/observations, or is absent.
If a core action itself is impossible, the GF score is at most 2.

---

### SC: Sequential Coherence -- 0~5

Check the state right before each action, not the order of the lines: is the object held or received, has the
robot arrived, was it passed first, was it taken by another robot earlier.

- 5: Every prerequisite action occurs before its dependent action; no ordering violations at all.
- 4: Exactly one minor ordering slip that does not prevent task completion.
- 3: A small number of minor ordering violations (roughly <=20% of actions), none of them critical.
- 2: Several ordering violations, or one moderately disruptive violation, though the plan remains partly executable.
- 1: Most of the sequence is disordered, or a critical violation blocks execution of a core action.
- 0: The sequence is incoherent throughout, or no real action sequence is given.

Violations include:
- Object used (put down, passed, poured) before it is picked up or received.
- RECEIVE before corresponding PASS.
- Robot waits for help that never arrives.
- Repeated identical actions on the same object.
- Too many physical actions in one 5-minute block (physically unrealistic).
If the prerequisite of a core action is broken, the SC score is at most 2.

---

### CQ: Collaboration Quality -- 0~5

First decide whether collaboration is REQUIRED (objects must move between rooms or robots, capability limits
prevent solo completion, or the task needs multi-room coordination) or NOT REQUIRED (each room's goals are
self-contained). If NOT REQUIRED, independent work with no collaboration steps earns the same score as any
other correct plan; only unnecessary coordination is penalised.
If REQUIRED, check each request, hand-over and resource split: the other robot, the object, and whether it is
completed.

Then evaluate:
- Necessity: Collaboration is used when truly needed. For simple tasks, unnecessary collaboration is penalized.
- Appropriateness: PASS/RECEIVE/HELP/ASK_HELP targets correct robots with correct objects.
  No "self-pass", no circular requests, no wrong targets.
- Efficiency: No redundant collaboration steps, no unnecessary intermediate transfers.
- Completeness: Requested collaborations are actually fulfilled.
- Resource conflicts: two robots assigned the same single object, so that one of them cannot do its step, is a
  critical coordination defect when it blocks a core goal.

Scoring:
- 5: Collaboration perfectly matches task needs -- either all collaborative actions are justified,
  correct, and completed successfully, OR collaboration was correctly recognized as unnecessary
  and the plan has none at all.
- 4: Collaboration (or correctly having none) is appropriate with only one very minor issue,
  such as slight redundancy that doesn't affect the outcome.
- 3: Collaboration is mostly appropriate but has one clear minor issue (a slightly wrong target,
  one redundant transfer).
- 2: Notable issues -- unnecessary collaboration for the task type, a self-pass, or one key
  required collaboration missing, though the rest of the plan is otherwise reasonable.
- 1: Collaboration is largely absent when required, or is mostly inappropriate/circular throughout.
- 0: Collaboration is completely absent despite being clearly required, or is severely
  circular/nonsensical throughout the plan.
